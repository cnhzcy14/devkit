# 共享 home 开发工具使用说明

本文只讲**怎么使用**。设计细节和清理项见 [devkit.md](devkit.md)。

## 1. 原则

- **root**：只装系统依赖，例如 `curl`、`git`、`build-essential`、`musl-tools`。
- **同名普通用户**：装所有开发工具，例如 Rust 工具、Neovim、node/npm、hunk、Trellis。
- 开发工具全部落在共享 home 的 `~/.devkit`，文件属主必须是普通用户。
- 完整安装**禁止以 root 运行**，否则工具会落到 `/root/.devkit`，宿主机看不到。

## 2. 文件

| 文件 | 作用 |
|---|---|
| `setup-ubuntu.sh` | 安装脚本，支持 `APT_ONLY` / `SKIP_APT` / `RUST_ONLY` / `NPM_ONLY` / `NVIM_ONLY` / `UPDATE_TS_PARSERS` |
| `devkit-up.sh` | 宿主机侧启动容器并执行安装 |
| `devkit-cleanup.sh` | 删除工具并还原 `.bashrc` |
| `docs/devkit.md` | 完整设计、制品布局、注意事项 |

## 3. 方式一：手工启容器 + docker exec

### 3.1 启动容器

沿用你原来的启动命令：

```bash
docker run -it --net=host -h "$(hostname)" \
  --name "${USER}_$(openssl rand -base64 8 | md5sum | cut -c1-8)" \
  -v "/home/${USER}:/home/${USER}" -w "/home/${USER}" \
  ubuntu:20.04 /bin/bash -c \
  "groupadd -g $(id -g) ${USER}; useradd -d /home/${USER} -s /bin/bash -g ${USER} -u $(id -u) ${USER}; su - ${USER}"
```

记下容器名，例如 `ye_cheng_d3a5c06b`。

### 3.2 root 装系统依赖

```bash
docker exec -it <容器名或ID> /bin/bash

APT_ONLY=1 bash /home/$USER/work/project/devkit/setup-ubuntu.sh
```

这一阶段只改容器内的 apt 系统依赖，不写开发工具到 home。

### 3.3 普通用户装 Rust 工具

```bash
docker exec -it <容器名或ID> /bin/bash -c "su - $USER"
```

进入后执行：

```bash
RUST_ONLY=1 SKIP_APT=1 bash /home/$USER/work/project/devkit/setup-ubuntu.sh
```

也可以不进入交互 shell，直接一条命令：

```bash
docker exec -it <容器名或ID> /bin/bash -c \
  "su - $USER -c 'RUST_ONLY=1 SKIP_APT=1 bash /home/$USER/work/project/devkit/setup-ubuntu.sh'"
```

### 3.4 验证

在宿主机新开一个终端：

```bash
source ~/.bashrc
yazi --version
rg --version
keifu --version
```

或在容器内：

```bash
docker exec -it <容器名或ID> /bin/bash -c "su - $USER"
source ~/.bashrc
yazi --version
rg --version
```

## 4. 方式二：一键启动

```bash
cd ~/work/project/devkit

./devkit-up.sh --rust    # 只装 Rust 工具
./devkit-up.sh --nvim    # 只装 Neovim/LazyVim
./devkit-up.sh --setup   # 装全部工具
./devkit-up.sh --apt     # 只装 apt 依赖
./devkit-up.sh           # 只启动容器并进入普通用户
```

`--rust` 内部等价于：

```bash
docker exec <容器> /bin/bash -c "APT_ONLY=1 bash setup-ubuntu.sh"
docker exec <容器> /bin/bash -c "su - $USER -c 'RUST_ONLY=1 SKIP_APT=1 bash setup-ubuntu.sh'"
docker exec -it <容器> su - "$USER"
```

## 5. Rust-only 安装内容

全部是 musl 静态二进制，位于 `~/.devkit/musl/bin`：

| 命令 | crate |
|---|---|
| `keifu` | `keifu` |
| `yazi` / `ya` | 官方 musl 预编译包，失败则源码编译 |
| `gitui` | `gitui` |
| `ducker` | `ducker` |
| `eza` | `eza` |
| `bat` | `bat` |
| `rg` | `ripgrep` |
| `fd` | `fd-find` |
| `btm` | `bottom` |
| `zoxide` | `zoxide` |

`~/.bashrc` 会追加一段带 `devkit` 标记的块，把
`~/.devkit/musl/bin` 加入 PATH。重复安装只会替换这一段，不会动其他内容。

## 6. 安装 hunk / Trellis（npm）

两者都通过 npm 安装：

| 工具 | npm 包 | 命令 |
|---|---|---|
| hunk | `hunkdiff` | `hunk` / `hunkdiff` |
| Trellis | `@mindfoldhq/trellis` | `trellis` / `tl` |

前置条件：Node.js 22 + Python >= 3.9（脚本用 uv 管 3.12）。

在已有容器里执行：

```bash
docker exec -it <容器名或ID> /bin/bash -c \
  "su - $USER -c 'NPM_ONLY=1 SKIP_APT=1 bash /home/$USER/work/project/devkit/setup-ubuntu.sh'"
```

`NPM_ONLY=1` 会安装 Node、uv/Python 3.12、hunk、Trellis，并跳过
Neovim/LazyVim。已经装好的 Rust 工具会自动跳过。

当前已实测版本：

```text
Node.js v22.20.0
npm 10.9.3
hunk 0.24.0        ← npm 包 hunkdiff
trellis 0.6.17     ← npm 包 @mindfoldhq/trellis
uv 0.13.7
Python 3.12.16
```

验证：

```bash
docker exec -it <容器名或ID> /bin/bash -c "su - $USER"
source ~/.bashrc
hunk --version
trellis --version
node --version
python3 --version
```

宿主机同样可用：

```bash
source ~/.bashrc
hunk --version
trellis --version
```

## 7. 镜像配置

### 6.1 默认国内源

默认值：

```bash
APT_MIRROR=cn
RUSTUP_DIST_SERVER=https://rsproxy.cn
RUSTUP_UPDATE_ROOT=https://rsproxy.cn/rustup
RUSTUP_INIT_URL=https://rsproxy.cn/rustup-init.sh
CARGO_REGISTRY=sparse+https://rsproxy.cn/index/
PY_MIRROR=https://mirrors.nju.edu.cn/github-release/astral-sh/python-build-standalone
```

### 6.2 换成公司源

```bash
APT_MIRROR=mirrors.corp.example.com \
RUSTUP_DIST_SERVER=https://mirrors.corp.example.com/rustup \
RUSTUP_UPDATE_ROOT=https://mirrors.corp.example.com/rustup \
RUSTUP_INIT_URL=https://mirrors.corp.example.com/rustup-init.sh \
CARGO_REGISTRY=sparse+https://mirrors.corp.example.com/crates.io-index/ \
RUST_ONLY=1 SKIP_APT=1 bash setup-ubuntu.sh
```

`APT_MIRROR` 的取值：

| 值 | 结果 |
|---|---|
| `cn` 或 `tuna` | 清华 Ubuntu 源 |
| `ustc` | 中科大 Ubuntu 源 |
| `off` | 不修改 apt 源 |
| `mirrors.corp.example.com` | 自动拼成 `http://.../ubuntu` |
| `http://.../ubuntu` | 直接使用完整 URL |

cargo 源会写入：

```text
~/.devkit/cargo/config.toml
```

查看当前配置：

```bash
cat ~/.devkit/cargo/config.toml
```

## 8. 安装 Neovim / LazyVim

前提：Rust 工具与 `NPM_ONLY` 阶段已完成。只补 Neovim + LazyVim 时用
`NVIM_ONLY=1`（跳过 Rust/Node/uv/npm 阶段，最快）：

```bash
docker exec -it <容器名或ID> /bin/bash -c \
  "su - $USER -c 'NVIM_ONLY=1 SKIP_APT=1 bash /home/$USER/work/project/devkit/setup-ubuntu.sh'"
```

`NVIM_ONLY=1` 只会执行：

```text
Neovim 最新 tag 源码编译 → .bashrc 托管块 → LazyVim starter → Lazy! sync
```

不带 `NVIM_ONLY=1` 的完整安装同样幂等，已经装好的 Rust/Node 工具会自动跳过：

```bash
docker exec -it <容器名或ID> /bin/bash -c \
  "su - $USER -c 'SKIP_APT=1 bash /home/$USER/work/project/devkit/setup-ubuntu.sh'"
```

Neovim 需要 GitHub 网络（源码、starter、插件）。脚本按“直连 → ghfast.top →
gh-proxy.com”的顺序重试；Lazy sync 失败不算安装失败，网络恢复后重跑即可续传。
容器内无 X11，`init.lua` 首行会写入 `vim.g.clipboard = "osc52"`。

nvim 路径已写入 `.bashrc` 托管块，宿主机 Ubuntu 20.04+ 和共享同一 home 的
Ubuntu 20.04+ 容器交互 shell 都直接可用。依赖 glibc >= 2.31（18.04、Alpine/musl
容器不行）。非交互 shell 不加载 `.bashrc`，请用绝对路径
`~/.devkit/nvim/bin/nvim`。

`NVIM_ONLY=1` 还会编译 musl 静态 `tree-sitter` CLI 并安装 wrapper。需要按 LazyVim
列表安装/更新 parser 时再加：

```bash
NVIM_ONLY=1 SKIP_APT=1 UPDATE_TS_PARSERS=1 bash setup-ubuntu.sh
```

parser 落在 `~/.local/share/nvim/site/parser`，且只在 20.04 容器内编译，保证
glibc 基线足够低。`uv` 默认安装官方 `x86_64-unknown-linux-musl` 静态包。

## 9. 清理

```bash
docker exec -it <容器名或ID> /bin/bash -c \
  "su - $USER -c 'bash /home/$USER/work/project/devkit/devkit-cleanup.sh'"
```

预览：

```bash
DRY_RUN=1 bash /home/$USER/work/project/devkit/devkit-cleanup.sh
```

清理会删除 `~/.devkit`、`.bashrc` 的 devkit 托管块；仅当安装创建过时才删除
`~/.local/share/nvim`、`~/.local/state/nvim`、`~/.cache/nvim`。

## 10. 常见问题

### 宿主机没有 yazi

先确认安装确实落在真实 home：

```bash
ls -l ~/.devkit/musl/bin/yazi
~/.devkit/musl/bin/yazi --version
```

如果 `~/.devkit` 不存在，通常是完整安装曾以 root 跑过，工具在
`/root/.devkit`。清理方式：

```bash
docker exec -it <容器名或ID> /bin/bash
HOME=/root DEVKIT_ROOT=/root/.devkit \
  bash /home/$USER/work/project/devkit/devkit-cleanup.sh
```

然后按普通用户重装。

### 交互 shell 有 yazi，非交互 shell 没有

你的 `.bashrc` 开头有：

```bash
case $- in
*i*) ;;
*) return ;;
esac
```

非交互 shell 不会执行后面的 PATH 配置。正常
`docker exec -it <容器> ... "su - $USER"` 进入的是交互 shell，不受影响。
如果需要在非交互命令里也生效，使用绝对路径：

```bash
/home/$USER/.devkit/musl/bin/yazi --version
```

或下一步给 `~/.local/bin` 增加带清理跟踪的软链。
