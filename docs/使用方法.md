# 共享 home 开发工具使用说明

本文只讲**怎么安装、怎么使用、怎么验证**；设计细节、制品布局和安全边界见
[devkit.md](devkit.md)。

最后更新：2026-11-27（Neovim 配置托管移出 devkit，原示例已移出到你的
dotfiles 仓库；tree-sitter CLI 改为 glibc，移除 wrapper；Lua LSP 仍使用
`emmylua_ls`）。

## 1. 安装边界与目录

### 1.1 谁能装、装到哪里

- **root**：只装系统依赖，例如 `curl`、`git`、`build-essential`、`musl-tools`、
  `libclang-dev`。不要在 root 下执行完整安装。
- **同名普通用户**：装所有开发工具，例如 Rust CLI、Neovim、node/npm、hunk、
  Trellis、Python 工具。
- 开发工具全部落在共享 home 的 `~/.devkit`，文件属主必须是普通用户。
- `setup-ubuntu.sh` **只能在 Ubuntu 容器内运行**；宿主机只负责
  `docker run` / `devkit-up.sh`。
- 完整安装**禁止以 root 运行**，否则工具会落到 `/root/.devkit`，宿主机看不到。

### 1.2 制品布局

```text
~/.devkit/
├── musl/bin/       musl 静态工具：Rust CLI、uv/uvx、neocmakelsp、emmylua_ls、
│                   tree-sitter CLI（glibc，供 Neovim）
├── clang/bin/      clangd（LSP + 内置 clang-format/clang-tidy）
├── git/bin/        静态编译的 git（自带 HTTPS）
├── nvim/           源码编译的 Neovim
├── node/           Node.js 22 LTS
├── npm-global/     hunk / Trellis / opencode 等 npm 全局包
├── uv-tool-bin/    basedpyright / ruff
├── uv-python/      uv 托管的 Python 3.12
├── venvs/          Trellis / opencode 各自的 Python venv
├── shims/          工具进程专用的 trellis/tl/opencode 启动器
├── cargo/ rustup/  Rust musl 工具链
├── openssl-musl/   ducker 需要的静态 OpenSSL
├── src/ state/
```

`.bashrc` 只追加一段带
`# >>> devkit (setup-ubuntu.sh) >>>` / `# <<< ... <<<` 标记的块；重复执行会先删
旧块再写新块，不影响其他内容。

## 2. 安装方式

### 2.1 一键启动（推荐）

在宿主机仓库目录执行：

```bash
cd ~/work/project/devkit

./devkit-up.sh --setup   # 启动容器 + root 装 apt 依赖 + 普通用户装全部工具
./devkit-up.sh --apt     # 只启动容器并装 apt 依赖
./devkit-up.sh           # 只启动容器并进入普通用户 shell
```

`--setup` 内部等价于：

```bash
docker exec -u 0 <容器> /bin/bash -c "APT_ONLY=1 bash setup-ubuntu.sh"
docker exec -u 0 <容器> /bin/bash -c \
  "su - $USER -c 'SKIP_APT=1 bash setup-ubuntu.sh'"
docker exec -it -u 0 <容器> su - "$USER"
```

`devkit-up.sh` 会把镜像、镜像源和版本变量写进容器
`/tmp/devkit-up.env`，root 与普通用户两个阶段都会自动加载。

### 2.2 手工启容器 + docker exec

如果沿用已有的 `docker run` 命令启动容器：

```bash
docker run -it --net=host -h "$(hostname)" \
  --name "${USER}_$(openssl rand -base64 8 | md5sum | cut -c1-8)" \
  -v "/home/${USER}:/home/${USER}" -w "/home/${USER}" \
  ubuntu:20.04 /bin/bash -c \
  "groupadd -g $(id -g) ${USER}; useradd -d /home/${USER} -s /bin/bash -g ${USER} -u $(id -u) ${USER}; su - ${USER}"
```

记下容器名，然后分两步安装。

**root 装系统依赖：**

```bash
docker exec -it <容器名或ID> /bin/bash
APT_ONLY=1 bash /home/$USER/work/project/devkit/setup-ubuntu.sh
```

**普通用户装全部工具：**

```bash
docker exec -it <容器名或ID> /bin/bash -c "su - $USER"
SKIP_APT=1 bash /home/$USER/work/project/devkit/setup-ubuntu.sh
```

也可以不进入交互 shell，一条命令完成：

```bash
docker exec -it <容器名或ID> /bin/bash -c \
  "su - $USER -c 'SKIP_APT=1 bash /home/$USER/work/project/devkit/setup-ubuntu.sh'"
```

安装是幂等的：已经装好的工具会跳过，网络失败后重跑只补未完成项。

### 2.3 使用内网/自制基座镜像

```bash
IMAGE=myreg.example.com/ubuntu20.04:dev \
APT_MIRROR=off \
./devkit-up.sh --setup
```

镜像必须满足：

- glibc 的 Ubuntu 20.04 或更新版本，x86_64；不能是 Alpine/musl；
- 有 `/bin/bash`、`/bin/sleep`、apt 和基本 coreutils；
- 镜像内已有同名用户时，UID/GID 必须与宿主机一致；
- 镜像已预装全部系统依赖时，加 `SKIP_APT=1` 跳过 root apt 阶段。

`devkit-up.sh` 启动容器时使用 `--user 0:0 --entrypoint /bin/sleep`，因此自制镜像
即使默认用户不是 root 或自带 ENTRYPOINT 也能常驻；后续 root 操作统一使用
`docker exec -u 0`。

## 3. 安装内容（按 setup-ubuntu.sh 章节）

### 3.1 章节顺序

```text
1 预检与系统依赖（root / APT_ONLY=1）
2 Rust musl 工具链与 CLI
3 C/C++：clangd、静态 git
4 Neovim（仅源码编译）
5 Node.js 与 TS/JS 工具
6 Python 运行时与工具 venv / shim
7 .bashrc 托管块
8 验收与清理
```

实际执行时，`.bashrc` 会在 Neovim 之前写入；这样即使后面 nvim 因网络失败，
Rust 工具也已经可用。

### 3.2 Rust 工具（musl 静态）

全部位于 `~/.devkit/musl/bin`，统一按 `x86_64-unknown-linux-musl` 构建或下载，
`readelf -l` 无 `INTERP` 段。

| 命令 | 来源 / crate | 说明 |
|---|---|---|
| `keifu` | `keifu` | 目录/项目跳转 |
| `yazi` / `ya` | 官方 musl 预编译包，失败则源码编译 | 文件管理器 |
| `gitui` | `gitui` | 替代 lazygit |
| `sk` | `skim` | 替代 fzf |
| `ducker` | `ducker` | Docker 管理 |
| `eza` | `eza` | 替代 `ls` |
| `bat` | `bat` | 替代 `cat` |
| `rg` | `ripgrep` | 搜索 |
| `fd` | `fd-find` | 文件查找 |
| `btm` | `bottom` | 系统监控 |
| `zoxide` | `zoxide` | 目录跳转 |
| `shuck` | `shuck-cli` | 替代 shfmt（Shell 格式化/语法检查） |
| `uv` / `uvx` | 官方 musl 静态包 | Python 运行时与工具管理 |
| `tree-sitter` | 源码编译的 glibc CLI | 供 Neovim 编译 Treesitter parser |

`tree-sitter` 是故意的 glibc 例外：CLI 需要 `dlopen` Neovim 使用的 glibc
`parser.so`，所以不按 musl 静态构建，也不再需要 wrapper。

### 3.3 C/C++ 工具

| 命令 | 位置 | 说明 |
|---|---|---|
| `clangd` | `~/.devkit/clang/bin/clangd` | C/C++ LSP，内置 clang-format 和 clang-tidy |
| `git` | `~/.devkit/git/bin/git` | 源码编译的静态 git，自带 HTTPS/libcurl，优先于系统 git |

只安装 `clangd`，不安装独立的 `clang-format` / `clang-tidy`：

- 格式化：编辑器按 `lsp_format = "fallback"` 保存时调用 clangd 内置
  clang-format（示例配置已移出到你的 dotfiles 仓库）；
- 诊断：clangd extra 传入 `--clang-tidy`。

命令行或 CI 需要独立的 `clang-format` / `clang-tidy` 时再单独安装。

### 3.4 编辑器相关工具

| 命令 | 位置 | 说明 |
|---|---|---|
| `neocmakelsp` | `~/.devkit/musl/bin/neocmakelsp` | CMake LSP，Rust 编写，官方 musl 静态包 |
| `emmylua_ls` | `~/.devkit/musl/bin/emmylua_ls` | Lua LSP，EmmyLua Analyzer Rust，官方 musl 静态包 |
| `nvim` | `~/.devkit/nvim/bin/nvim` | 源码编译的 Neovim |

> **neocmakelsp 是 Rust 写的工具**（上游仓库 `neocmakelsp/neocmakelsp`）。
> 它和 `yazi` 一样由 GitHub release 直接提供 musl 静态包，脚本只下载
> 并校验静态链接，不再走 cargo 编译。
>
> **Lua LSP 已切换为 EmmyLua Analyzer Rust**（`emmylua_ls`，上游仓库
> `EmmyLuaLs/emmylua-analyzer-rust`）。旧的 `lua-language-server`
> （glibc 包，位于 `~/.devkit/lua-ls`）不再安装；重跑新版安装时会自动清理旧的
> `lua-ls` 目录。

默认版本（可用同名环境变量覆盖）：

```text
neocmakelsp 0.12.0
emmylua_ls  0.25.1
shuck       0.2.11
clangd      22.1.6
tree-sitter 0.27.2（必须 >= 0.26.1）
```

验证：

```bash
neocmakelsp --version
emmylua_ls --version          # emmylua_ls 0.25.1
readelf -l ~/.devkit/musl/bin/emmylua_ls | grep INTERP || echo "static"
```

### 3.5 Node.js、npm 与 TS/JS 工具

Node.js 22 LTS 装在 `~/.devkit/node`，npm 全局包装在 `~/.devkit/npm-global`：

| 工具 | npm 包 | 命令 |
|---|---|---|
| hunk | `hunkdiff` | `hunk` / `hunkdiff` |
| Trellis | `@mindfoldhq/trellis` | `trellis` / `tl` |
| opencode | `@opencode/cli` | `opencode` / `opencode2` |

opencode 默认安装；不需要时用 `WITH_OPENCODE=0` 跳过。它的 npm 包带 postinstall
脚本，会按平台选择原生二进制，因此不要加 `--ignore-scripts`。

hunk 默认固定 `0.24.0`：`0.24.1` 的 linux 平台包在 npmmirror 上可能尚未同步。
可用 `HUNK_VERSION=...` 覆盖。

验证：

```bash
node --version
npm --version
hunk --version
trellis --version
opencode --version
```

### 3.6 Python 3.12 与工具 venv

Python 3.12 由 uv 托管，只装一份：

```text
~/.devkit/uv-python/                    # uv 管理的 Python 3.12
~/.devkit/python-bin/python3            # 私有解释器，不加入全局 PATH
~/.devkit/venvs/trellis/                # Trellis 的 venv
~/.devkit/venvs/opencode/               # opencode 的 venv
~/.devkit/shims/trellis|tl|opencode     # 只为工具进程注入对应 venv 的 PATH
```

容器交互 shell 里的 `python3` 仍然是镜像自带的系统 Python，不会被 devkit 覆盖。

`basedpyright` 与 `ruff` 通过 `uv tool install` 装到 `~/.devkit/uv-tool-bin`，
与工具 venv 隔离，但已在 `.bashrc` 的 PATH 中：

```bash
basedpyright --version
ruff --version
~/.devkit/python-bin/python3 --version
```

给 opencode 的脚本装包，只装进它的 venv：

```bash
uv pip install --python ~/.devkit/venvs/opencode/bin/python <包名>
```

CN 环境下默认走清华 PyPI 源，可用 `PYPI_INDEX` 覆盖。

## 4. Neovim

### 4.1 安装流程

完整安装的 Neovim 章节只做一件事：

```text
Neovim 最新 tag 源码编译
```

重跑即可续传：

```bash
docker exec -it <容器名或ID> /bin/bash -c \
  "su - $USER -c 'SKIP_APT=1 bash /home/$USER/work/project/devkit/setup-ubuntu.sh'"
```

Neovim 需要 GitHub 网络（源码和编译依赖）。LazyVim starter、插件同步、parser
清单都由你的 Neovim 配置负责，不再由 devkit 安装。

容器内无 X11；示例配置（在你的 dotfiles 仓库的 `lua/config/options.lua`）里设置
`vim.g.clipboard = "osc52"`，通过终端访问宿主机剪贴板。

nvim 路径已写入 `.bashrc` 托管块。依赖 glibc >= 2.31（18.04、Alpine/musl 容器
不行）。非交互 shell 不加载 `.bashrc`，请用绝对路径
`~/.devkit/nvim/bin/nvim`。

### 4.2 配置由 dotfiles 管理

devkit 不再克隆 LazyVim starter，也不再写 `~/.config/nvim`（包括
`devkit.lua`、`options.lua`、parser 清单）。原 `dotfiles/nvim/` 临时目录已移出
devkit，等价的增量配置在你的 dotfiles 仓库中：

- `lua/plugins/devkit.lua`：关闭 Mason、启用 clangd/cmake/python extras、
  用 `emmylua_ls` 替代 `lua_ls`、conform 使用 shuck；
- `lua/plugins/treesitter.lua`：显式 parser 清单；
- `lua/config/options.lua`：OSC52 剪贴板、`basedpyright`。

把这些文件合并到你的 LazyVim/dotfiles 配置后，首次启动会按
`ensure_installed` 安装 parser。需要手动更新时在 Neovim 里执行 `:TSUpdate`。
parser 仍在 20.04 容器内编译，保证 glibc 基线足够低。

验证：

```bash
command -v nvim
nvim --version | head -1
```

在 Neovim 内用 `:checkhealth vim.lsp` / `:LspInfo` 确认
`emmylua_ls`、`clangd`、`basedpyright` 正常启动，且没有 `lua_ls`。

## 5. PATH 与 `.bashrc`

`.bashrc` 托管块负责：

- 把 `shims`、`musl/bin`、`node/bin`、`npm-global/bin`、`uv-tool-bin`、
  `cargo/bin` 加入 PATH；
- 把 `clang/bin`、`git/bin`、`nvim/bin` 放在系统 PATH 之前；
- 设置 `GIT_SSL_CAINFO`、`NPM_CONFIG_*`、`RUSTUP_HOME`、`CARGO_HOME`、
  `UV_*` 等环境变量；
- 提供 `y()` 包装函数，退出 yazi 时切换到最后浏览目录。

注意：

- `python-bin` 故意不加入 PATH，避免覆盖容器的系统 `python3`；
- 非交互 shell 不加载 `.bashrc`，脚本或 CI 请用绝对路径；
- 修改后执行 `source ~/.bashrc` 或重开终端。

```bash
source ~/.bashrc
command -v yazi rg neocmakelsp emmylua_ls nvim
```

## 6. 镜像配置与常用开关

### 6.1 默认国内源

```bash
APT_MIRROR=cn
RUSTUP_DIST_SERVER=https://rsproxy.cn
RUSTUP_UPDATE_ROOT=https://rsproxy.cn/rustup
RUSTUP_INIT_URL=https://rsproxy.cn/rustup-init.sh
CARGO_REGISTRY=sparse+https://rsproxy.cn/index/
NPM_REGISTRY=https://registry.npmmirror.com
NODE_DIST=https://npmmirror.com/mirrors/node
GH_MIRRORS="https://ghfast.top/ https://gh-proxy.com/"
PY_MIRROR=https://mirrors.nju.edu.cn/github-release/astral-sh/python-build-standalone
```

`MIRROR=cn` 时脚本会先探测各国内镜像；不可达项自动回退官方源，并在预检阶段
打印提示。

### 6.2 换成公司源

```bash
APT_MIRROR=mirrors.corp.example.com \
RUSTUP_DIST_SERVER=https://mirrors.corp.example.com/rustup \
RUSTUP_UPDATE_ROOT=https://mirrors.corp.example.com/rustup \
RUSTUP_INIT_URL=https://mirrors.corp.example.com/rustup-init.sh \
CARGO_REGISTRY=sparse+https://mirrors.corp.example.com/crates.io-index/ \
NPM_REGISTRY=https://npm.corp.example.com \
NODE_DIST=https://mirrors.corp.example.com/node \
GH_MIRRORS="https://git.corp.example.com/github-proxy/" \
SKIP_APT=1 bash setup-ubuntu.sh
```

`APT_MIRROR` 取值：

| 值 | 结果 |
|---|---|
| `cn` 或 `tuna` | 清华 Ubuntu 源 |
| `ustc` | 中科大 Ubuntu 源 |
| `off` | 不修改 apt 源，适合镜像内已是公司内网源 |
| `mirrors.corp.example.com` | 自动拼成 `http://.../ubuntu` |
| `http://.../ubuntu` | 直接使用完整 URL |

cargo 源写入 `~/.devkit/cargo/config.toml`，查看：

```bash
cat ~/.devkit/cargo/config.toml
```

## 7. 验证与常见问题

### 7.1 验收命令

```bash
source ~/.bashrc

# Rust / 编辑器工具
keifu --version
yazi --version
rg --version
neocmakelsp --version
emmylua_ls --version

# C/C++ 与 git
clangd --version
git --version
ls ~/.devkit/git/libexec/git-core/git-remote-https

# Node/npm
node --version
hunk --version
trellis --version

# Python
basedpyright --version
ruff --version
~/.devkit/python-bin/python3 --version

# Neovim
nvim --version | head -1
```

安装脚本最后会自动打印验收表：静态工具逐项检查 `INTERP`，缺失或动态链接会
以红色标出并让安装失败。

### 7.2 宿主机没有 yazi / 工具不在 PATH

先确认安装确实落在真实 home：

```bash
ls -l ~/.devkit/musl/bin/yazi
~/.devkit/musl/bin/yazi --version
grep -n 'devkit (setup-ubuntu.sh)' ~/.bashrc
source ~/.bashrc
command -v yazi
```

常见原因：

- `~/.devkit` 不存在：完整安装曾以 root 跑过，工具在 `/root/.devkit`；
- 二进制存在但 `command -v` 找不到：`.bashrc` 块没写入或当前 shell 没重新加载；
- 绝对路径执行报 `No such file or directory` 但文件存在：拿到了动态链接版本，
  用 `readelf -l <bin> | grep INTERP` 检查。

以 root 跑错位置时，先清理再按普通用户重装：

```bash
docker exec -it <容器> /bin/bash
HOME=/root DEVKIT_ROOT=/root/.devkit \
  bash /home/$USER/work/project/devkit/devkit-cleanup.sh
```

### 7.3 交互 shell 有工具，非交互 shell 没有

如果 `.bashrc` 开头有：

```bash
case $- in
*i*) ;;
*) return ;;
esac
```

非交互 shell 不会执行后面的 PATH 配置。正常
`docker exec -it <容器> ... "su - $USER"` 进入的是交互 shell，不受影响。
脚本/CI 请用绝对路径，例如：

```bash
/home/$USER/.devkit/musl/bin/yazi --version
```

### 7.4 emmylua_ls 没有启动

按顺序检查：

```bash
# 二进制
command -v emmylua_ls
emmylua_ls --version

# Neovim 是否能找到
nvim --headless -c 'lua print(vim.fn.executable("emmylua_ls"))' +qa

# 配置是否加载（路径以你合并后的 dotfiles 为准）
nvim ~/.config/nvim/lua/plugins/devkit.lua
:LspInfo
```

- `:LspInfo` 里还有 `lua_ls`：说明你的配置仍启用 LazyVim 默认 `lua_ls`，或
  `devkit.lua` 被其他文件覆盖；确认已从你的 dotfiles 仓库合并
  `lua/plugins/devkit.lua`。
- `emmylua_ls` 启动后立刻退出：看 `:messages`；需要日志时临时用
  `cmd = { "emmylua_ls", "--log-path", "/tmp/emmylua.log" }`。
- 项目里的 `.emmyrc.json` 格式错误会导致工作区加载失败；先用 JSON 校验工具
  检查，或临时移走该文件。
- 只想为单个项目启用：在项目根放 `.emmyrc.json`，`emmylua_ls` 会自动以该目录
  为 workspace。

### 7.5 Neovim 配置 / parser 失败

- 插件下载、Lazy sync 失败由你的 Neovim 配置负责；网络恢复后重试即可；
- parser 失败：在 nvim 内执行 `:TSInstall` / `:TSUpdate`，清单见你 dotfiles
  仓库中的 `lua/plugins/treesitter.lua`；
- 容器内没有 X11 是正常的，剪贴板通过 OSC52 走终端（示例配置已设置）。

### 7.6 旧版 `lua-language-server` 残留

新版安装会自动删除 `~/.devkit/lua-ls`。如果只想手动清理：

```bash
rm -rf ~/.devkit/lua-ls
command -v lua-language-server || echo "已移除"
```

`.bashrc` 托管块重跑后会去掉旧的 `lua-ls/bin` PATH 条目。

## 8. 清理

清理脚本只操作共享 home 中的文件，宿主机或容器内都能执行，使用安装时的同一个
普通用户：

```bash
bash ~/work/project/devkit/devkit-cleanup.sh
```

通过容器执行：

```bash
docker exec -it -u 0 <容器名或ID> /bin/bash -c \
  "su - $USER -c 'bash /home/$USER/work/project/devkit/devkit-cleanup.sh'"
```

先预览：

```bash
DRY_RUN=1 bash ~/work/project/devkit/devkit-cleanup.sh
```

删除内容：

- `~/.devkit` 整个目录（包括 `emmylua_ls`、neocmakelsp、nvim、node、Python）；
- `.bashrc` 的 devkit 托管块；
- 仅当 setup 创建过时才删除 `~/.local/share/nvim`、`~/.local/state/nvim`、
  `~/.cache/nvim`；
- 不再删除或还原 `~/.config/nvim`；如果发现旧版 `.devkit-managed` 标记，只提示
  手动处理。

apt 源替换发生在容器内的 `/etc/apt/sources.list`（并留 `.devkit.bak`），属于
容器系统层，不在 home 清理范围；容器重建即消失。
