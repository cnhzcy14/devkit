# 共享 home 开发工具使用说明

本文只讲**怎么使用**。设计细节和清理项见 [devkit.md](devkit.md)。

## 1. 原则

- **root**：只装系统依赖，例如 `curl`、`git`、`build-essential`、`musl-tools`。
- **同名普通用户**：装所有开发工具，例如 Rust 工具、Neovim、node/npm、hunk、Trellis。
- 开发工具全部落在共享 home 的 `~/.devkit`，文件属主必须是普通用户。
- **安装脚本只能在 Ubuntu 容器内运行**；宿主机只负责 `docker run` / `devkit-up.sh`。
- 完整安装**禁止以 root 运行**，否则工具会落到 `/root/.devkit`，宿主机看不到。

## 2. 文件

| 文件 | 作用 |
|---|---|
| `setup-ubuntu.sh` | 安装脚本，支持 `APT_ONLY` / `SKIP_APT` / `UPDATE_TS_PARSERS` 等开关 |
| `devkit-up.sh` | 宿主机侧启动容器并执行安装 |
| `devkit-cleanup.sh` | 删除工具并还原 `.bashrc` |
| `docs/devkit.md` | 完整设计、制品布局、注意事项 |

## 3. 方式一：手工启容器 + docker exec

### 3.1 启动容器

沿用你原来的启动命令：

```bash
docker run -it --net=host -h "$(hostname)" \
  --name "${USER}_$(openssl rand -base64 8 | md5sum | cut -c1-8)" \
  -v "/home/${USER}:/home/${USER}" -w "/home/${USER}" \
  ubuntu:20.04 /bin/bash -c \
  "groupadd -g $(id -g) ${USER}; useradd -d /home/${USER} -s /bin/bash -g ${USER} -u $(id -u) ${USER}; su - ${USER}"
```

记下容器名，例如 `ye_cheng_d3a5c06b`。

> 如果用的是内网/自制 Ubuntu 20.04 镜像（例如 `IMAGE=myreg/ubuntu20.04:dev`），
> 推荐直接用 `IMAGE=... ./devkit-up.sh --setup`；手工启动时如果镜像里已有同名
> 用户，要跳过 `groupadd`/`useradd`，并确保 UID/GID 与宿主机一致。

### 3.2 root 装系统依赖

```bash
docker exec -it <容器名或ID> /bin/bash

APT_ONLY=1 bash /home/$USER/work/project/devkit/setup-ubuntu.sh
```

这一阶段只改容器内的 apt 系统依赖，不写开发工具到 home。

### 3.3 普通用户装全部工具

```bash
docker exec -it <容器名或ID> /bin/bash -c "su - $USER"
```

进入后执行：

```bash
SKIP_APT=1 bash /home/$USER/work/project/devkit/setup-ubuntu.sh
```

也可以不进入交互 shell，直接一条命令：

```bash
docker exec -it <容器名或ID> /bin/bash -c \
  "su - $USER -c 'SKIP_APT=1 bash /home/$USER/work/project/devkit/setup-ubuntu.sh'"
```

### 3.4 验证

在宿主机新开一个终端：

```bash
source ~/.bashrc
yazi --version
rg --version
keifu --version
```

或在容器内：

```bash
docker exec -it <容器名或ID> /bin/bash -c "su - $USER"
source ~/.bashrc
yazi --version
rg --version
```

## 4. 方式二：一键启动

```bash
cd ~/work/project/devkit

./devkit-up.sh --setup   # 装全部工具
./devkit-up.sh --apt     # 只装 apt 依赖
./devkit-up.sh           # 只启动容器并进入普通用户
```

`--setup` 内部等价于：

```bash
docker exec <容器> /bin/bash -c "APT_ONLY=1 bash setup-ubuntu.sh"
docker exec <容器> /bin/bash -c "su - $USER -c 'SKIP_APT=1 bash setup-ubuntu.sh'"
docker exec -it <容器> su - "$USER"
```

## 5. Rust 工具链与 CLI（musl 静态）

全部是 musl 静态二进制，位于 `~/.devkit/musl/bin`：

| 命令 | crate |
|---|---|
| `keifu` | `keifu` |
| `yazi` / `ya` | 官方 musl 预编译包，失败则源码编译 |
| `gitui` | `gitui`（替代 lazygit） |
| `sk` | `skim`（替代 fzf） |
| `ducker` | `ducker` |
| `eza` | `eza` |
| `bat` | `bat` |
| `rg` | `ripgrep` |
| `fd` | `fd-find` |
| `btm` | `bottom` |
| `zoxide` | `zoxide` |
| `shuck` | `shuck-cli`（替代 shfmt：格式化、语法检查） |
| `stylua` | `stylua`（Lua 格式化） |
| `uv` / `uvx` | 官方 musl 静态预编译包（Python 管理工具） |
| `tree-sitter` | 源码编译的 musl 静态 CLI（供 Neovim parser 使用） |

非 Rust 包但同属编辑器工具链：

| 命令 | 位置 | 说明 |
|---|---|---|
| `neocmakelsp` | `~/.devkit/musl/bin/neocmakelsp` | 官方 musl 静态包，CMake LSP |
| `lua-language-server` | `~/.devkit/lua-ls/bin/lua-language-server` | 官方 linux-x64 包（glibc 2.17+），Lua LSP |

`~/.bashrc` 会追加一段带 `devkit` 标记的块，把 `~/.devkit/musl/bin`、
`~/.devkit/lua-ls/bin` 加入 PATH。重复安装只会替换这一段，不会动其他内容。

```bash
shuck --version          # 0.2.11
stylua --version         # 2.6.0
neocmakelsp --version    # 0.12.0
lua-language-server --version   # 3.19.2
readelf -l ~/.devkit/musl/bin/shuck | grep INTERP   # 无输出（静态）
```

### C/C++（clangd）

只安装 `clangd` 到 `~/.devkit/clang/bin`。它同时提供：

- C/C++ LSP（补全、跳转、诊断）；
- 格式化：内置 clang-format，LazyVim 保存时通过 `lsp_format = "fallback"` 调用；
- clang-tidy 诊断：LazyVim 的 clangd extra 已传 `--clang-tidy`。

没有独立的 `clang-format` / `clang-tidy` 命令；命令行或 CI 需要时再单独安装。

```bash
clangd --version
```

## 6. Node.js、Python 与 TS/JS 工具

三者都通过 npm 安装到 `~/.devkit/npm-global`：

| 工具 | npm 包 | 命令 |
|---|---|---|
| hunk | `hunkdiff` | `hunk` / `hunkdiff` |
| Trellis | `@mindfoldhq/trellis` | `trellis` / `tl` |
| opencode | `@opencode/cli` | `opencode` / `opencode2` |

opencode 默认安装；不需要时用 `WITH_OPENCODE=0` 跳过。它的 npm 包带一个
postinstall 脚本，会按平台选择原生二进制，因此不要加 `--ignore-scripts`。
如果 home 里已有手动安装的 opencode（例如 `~/.opencode/bin/opencode`），
devkit 仍会装自己的一份到 `~/.devkit/npm-global/bin`，并通过 PATH 顺序优先使用。

前置条件：Node.js 22；Python 3.12 由脚本通过 uv 自动安装。Trellis 与 opencode
各用自己的 venv（`~/.devkit/venvs/`），不会覆盖容器的系统 `python3`。

完整安装会依次处理 Node、npm 工具和 Python。已有容器里重跑即可
（幂等，已装好的会跳过）：

```bash
docker exec -it <容器名或ID> /bin/bash -c \
  "su - $USER -c 'SKIP_APT=1 bash /home/$USER/work/project/devkit/setup-ubuntu.sh'"
```

Python 3.12 只装一份，Trellis 和 opencode 各有独立 venv：

```text
~/.devkit/python-bin/python3          # 私有解释器，不加入全局 PATH
~/.devkit/venvs/trellis/              # Trellis 的 venv
~/.devkit/venvs/opencode/             # opencode 的 venv
~/.devkit/shims/trellis|tl|opencode   # 只在工具进程内注入对应 venv 的 PATH
```

给 opencode 的脚本装包，只装进它的 venv：

```bash
uv pip install --python ~/.devkit/venvs/opencode/bin/python <包名>
```

容器交互 shell 里的 `python3` 仍然是镜像自带的系统 Python，不会被 devkit 覆盖。

`basedpyright` 与 `ruff` 通过 `uv tool install` 装到 `~/.devkit/uv-tool-bin`，
与各工具 venv 隔离，但已在 `.bashrc` PATH 中，宿主机和容器都能直接使用。
CN 环境下默认走清华 PyPI 源，可用 `PYPI_INDEX` 覆盖。

当前已实测版本：

```text
Node.js v22.20.0
npm 10.9.3
hunk 0.24.0        ← npm 包 hunkdiff
trellis 0.6.17     ← npm 包 @mindfoldhq/trellis
uv 0.13.7
Python 3.12.16
```

验证：

```bash
docker exec -it <容器名或ID> /bin/bash -c "su - $USER"
source ~/.bashrc
hunk --version
trellis --version
node --version
~/.devkit/python-bin/python3 --version
```

宿主机同样可用：

```bash
source ~/.bashrc
hunk --version
trellis --version
```

## 7. 镜像配置

### 7.1 默认国内源

默认值：

```bash
APT_MIRROR=cn
RUSTUP_DIST_SERVER=https://rsproxy.cn
RUSTUP_UPDATE_ROOT=https://rsproxy.cn/rustup
RUSTUP_INIT_URL=https://rsproxy.cn/rustup-init.sh
CARGO_REGISTRY=sparse+https://rsproxy.cn/index/
NPM_REGISTRY=https://registry.npmmirror.com
NODE_DIST=https://npmmirror.com/mirrors/node
GH_MIRRORS="https://ghfast.top/ https://gh-proxy.com/"
PY_MIRROR=https://mirrors.nju.edu.cn/github-release/astral-sh/python-build-standalone
```

### 7.2 换成公司源

```bash
APT_MIRROR=mirrors.corp.example.com \
RUSTUP_DIST_SERVER=https://mirrors.corp.example.com/rustup \
RUSTUP_UPDATE_ROOT=https://mirrors.corp.example.com/rustup \
RUSTUP_INIT_URL=https://mirrors.corp.example.com/rustup-init.sh \
CARGO_REGISTRY=sparse+https://mirrors.corp.example.com/crates.io-index/ \
NPM_REGISTRY=https://npm.corp.example.com \
NODE_DIST=https://mirrors.corp.example.com/node \
GH_MIRRORS="https://git.corp.example.com/github-proxy/" \
SKIP_APT=1 bash setup-ubuntu.sh
```

`APT_MIRROR` 的取值：

| 值 | 结果 |
|---|---|
| `cn` 或 `tuna` | 清华 Ubuntu 源 |
| `ustc` | 中科大 Ubuntu 源 |
| `off` | 不修改 apt 源，适合镜像内已是公司内网源 |
| `mirrors.corp.example.com` | 自动拼成 `http://.../ubuntu` |
| `http://.../ubuntu` | 直接使用完整 URL |

### 7.3 内网自制基座镜像

```bash
IMAGE=myreg.example.com/ubuntu20.04:dev \
APT_MIRROR=off \
./devkit-up.sh --setup
```

`devkit-up.sh` 启动容器时使用 `--user 0:0 --entrypoint /bin/sleep`，因此自制镜像
即使默认用户不是 root 或自带 ENTRYPOINT 也能常驻；后续 root 操作统一使用
`docker exec -u 0`。镜像必须满足：

- glibc Ubuntu 20.04 或更新版本（不能是 Alpine/musl），x86_64；
- 有 `/bin/bash`、`/bin/sleep`、apt 和 coreutils；
- 镜像内已有同名用户时，UID/GID 必须与宿主机一致，否则脚本会直接报错；
- 镜像已预装好全部系统依赖时，再加 `SKIP_APT=1` 跳过 root apt 阶段。

> `devkit-up.sh` 会把 `MIRROR`、`APT_MIRROR`、`SKIP_APT`、`RUSTUP_*`、
> `CARGO_REGISTRY`、`NPM_REGISTRY`、`NODE_DIST`、`GH_MIRRORS`、`PY_MIRROR`、
> `OPENSSL_TARBALL` 及版本变量写进容器 `/tmp/devkit-up.env` 并自动加载。

cargo 源会写入：

```text
~/.devkit/cargo/config.toml
```

查看当前配置：

```bash
cat ~/.devkit/cargo/config.toml
```

## 8. 安装 Neovim / LazyVim

完整安装的 Neovim 章节会依次执行：

```text
Neovim 最新 tag 源码编译 → LazyVim starter → Lazy! sync → Treesitter parser
```

重跑完整安装即可（幂等，已装好的工具会自动跳过）：

```bash
docker exec -it <容器名或ID> /bin/bash -c \
  "su - $USER -c 'SKIP_APT=1 bash /home/$USER/work/project/devkit/setup-ubuntu.sh'"
```

Neovim 需要 GitHub 网络（源码、starter、插件）。脚本按“直连 → ghfast.top →
gh-proxy.com”的顺序重试；Lazy sync 失败不算安装失败，网络恢复后重跑即可续传。
容器内无 X11，`init.lua` 首行会写入 `vim.g.clipboard = "osc52"`。

nvim 路径已写入 `.bashrc` 托管块，宿主机 Ubuntu 20.04+ 和共享同一 home 的
Ubuntu 20.04+ 容器交互 shell 都直接可用。依赖 glibc >= 2.31（18.04、Alpine/musl
容器不行）。非交互 shell 不加载 `.bashrc`，请用绝对路径
`~/.devkit/nvim/bin/nvim`。

`tree-sitter` CLI 在 Rust 章节编译为 musl 静态二进制并带 wrapper。需要按
LazyVim 列表安装/更新 parser 时加：

```bash
SKIP_APT=1 UPDATE_TS_PARSERS=1 bash setup-ubuntu.sh
```

parser 落在 `~/.local/share/nvim/site/parser`，且只在 20.04 容器内编译，保证
glibc 基线足够低。`uv` 默认安装官方 `x86_64-unknown-linux-musl` 静态包；它安装的
Python 3.12 位于 `~/.devkit/uv-python`，不加入全局 PATH。

## 9. 清理

清理脚本只操作共享 home 中的文件，可以在宿主机或容器内执行，用同一个普通用户即可：

```bash
bash ~/work/project/devkit/devkit-cleanup.sh
```

也可以通过容器执行：

```bash
docker exec -it -u 0 <容器名或ID> /bin/bash -c \
  "su - $USER -c 'bash /home/$USER/work/project/devkit/devkit-cleanup.sh'"
```

预览：

```bash
DRY_RUN=1 bash ~/work/project/devkit/devkit-cleanup.sh
```

清理会删除 `~/.devkit`、`.bashrc` 的 devkit 托管块；仅当安装创建过时才删除
`~/.local/share/nvim`、`~/.local/state/nvim`、`~/.cache/nvim`。

## 10. 常见问题

### 宿主机没有 yazi

先确认安装确实落在真实 home：

```bash
ls -l ~/.devkit/musl/bin/yazi
~/.devkit/musl/bin/yazi --version
```

如果 `~/.devkit` 不存在，通常是完整安装曾以 root 跑过，工具在
`/root/.devkit`。清理方式：

```bash
docker exec -it <容器名或ID> /bin/bash
HOME=/root DEVKIT_ROOT=/root/.devkit \
  bash /home/$USER/work/project/devkit/devkit-cleanup.sh
```

然后按普通用户重装。

### 交互 shell 有 yazi，非交互 shell 没有

你的 `.bashrc` 开头有：

```bash
case $- in
*i*) ;;
*) return ;;
esac
```

非交互 shell 不会执行后面的 PATH 配置。正常
`docker exec -it <容器> ... "su - $USER"` 进入的是交互 shell，不受影响。
如果需要在非交互命令里也生效，使用绝对路径：

```bash
/home/$USER/.devkit/musl/bin/yazi --version
```

或下一步给 `~/.local/bin` 增加带清理跟踪的软链。
